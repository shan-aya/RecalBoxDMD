## 🎯 Overview

**RecalBoxDMD Toolkit** is an optimized fork of **RetroBoxLED** by Jamyz, specifically designed to solve **display lag** issues on systems with a large number of files (MAME fullset, FBNeo, etc.).

### 🔥 The problem solved

The original version by Jamyz read **PNG and GIF** files directly from the SD card. On systems like **MAME fullset** (30,000+ games), this approach caused:

```
❌ Original problem:
   - Opening /systems/mame/ folder with 30,000 files
   - ESP32 lists all files → freezes for several seconds
   - PNG decoding on ESP32 → slow, insufficient memory
   - Between each game: black screen or visible lag
```

**The "Raw565 Edition"** pre-converts all images on the PC (via the Python script) into a **raw RGB565 format** directly displayable by the ESP32:

```
✅ raw565 solution:
   1. Script converts each PNG → .raw565 file (8192 bytes, ready to use)
   2. Each GIF → .raw565pack (concatenated frames) + .meta (timings)
   3. ESP32 reads the raw565 file and sends it directly to the LED panel
   4. No decoding, no lag: near-instant display
```

| Metric | Original PNG/GIF | Raw565 Edition |
|--------|-----------------|----------------|
| Display time | 500ms – 3s+ | **5–15ms** |
| RAM needed | 50-100 KB | **8 KB** |
| MAME fullset lag | Freeze 5-10s | **0** |
| Compatibility | All systems | **"L"-flagged systems** |

### The mask system

For very large systems flagged **"L"** (Large / Slow, like MAME or FBNeo), the firmware uses a mask mechanism:

1. The script detects systems with >800 individual files
2. It marks these systems as **"L"** in `systems_cache.dat`
3. When the ESP32 receives a game from this system:
   - It immediately displays the **system default raw565** from RAM cache
   - In parallel, an async task decodes the specific PNG
   - When decoding is done, the specific image replaces the mask
4. Result: **the user never sees a black screen**, the panel stays active

> **💡 Result**: No more seconds of waiting between games. Display is near-instant even with a 30,000-file MAME fullset!

> **💡 Constraints**: You must go through the script to prepare the SD card. You cannot add images to the SD card on the fly.

## 🆕 What's New

### 🎯 Recalbox version handling (Mode 1 & Mode 3)

Recalbox stores marquee/logo images differently depending on the installed version **and** on the options chosen in Recalbox's Scraper tab. To avoid grabbing the wrong artwork (box art instead of the logo, for instance), Mode 1 and Mode 3 now expose a **"Recalbox version"** panel:

- A **10.x / 9.x / legacy** selector that automatically determines the correct `gamelist.xml` tag (`<logo>`, `<thumbnail>` or `<image>`) and the correct media folder (`media/wheels/`, `media/thumbnails/` or `media/images/`).
- A **"How to scrape?"** button that shows, for the selected version, an annotated screenshot of Recalbox's Scraper tab indicating exactly which field to set (see [Recalbox Scraping Tutorial](#-recalbox-scraping-tutorial)).
- A **"Clean folders before scraping"** button: deletes (with confirmation and a file-count preview) the images already present in the matching media folder, system by system, so you can run a fresh, complete Recalbox scrape.
- The chosen version is remembered (preferences file) and shared between Mode 1 (Main tab) and Mode 3 (Advanced tab).

### 🔎 Mode 8 — Missing images check

New mode in the Advanced tab: scans the ROMs folder's `gamelist.xml` files and reports, for each system and game, whether the expected image (per the selected version profile) actually exists on disk. A report is generated, and an additional option lets you compare against the temporary working folder (and, optionally, the physical SD card) to tell apart images missing on the ROMs side, not converted, or not copied to the SD card.

### 💾 Resumable SD card copy

Copying to the physical SD card (the blinking button shown after a run) now survives an interruption (unplugging, crash): atomic file writes, detection of an incomplete previous copy on next launch, and a dedicated button to retry only the failed files instead of the whole copy.

## 🎨 Recalbox Scraping Tutorial

For the LED panel to display the right artwork, you must first **scrape** your ROMs in Recalbox — and set up the Scraper tab correctly **for your version**. This is exactly what the Mode 1/3 **"How to scrape?"** button does (annotated screenshots right inside the app), summarized here:

### Recalbox 10.x (dedicated logo field)

Since Recalbox 10.x, the **SCRAPER → SCRAPE NOW** menu has a dedicated **"SELECT LOGO TYPE"** field (still shown in English on some alpha/beta builds):

1. Set **"SELECT LOGO TYPE"** to **"CLEAR"**
2. Do NOT set that value on **"Select image type"** — that field is for the main visual (in-game screenshot, box art...), not the logo
3. Run the scrape

Files are stored in `media/wheels/` for each system, referenced by the `<logo>` tag in `gamelist.xml`. → Choose the **10.x** profile in the tool.

### Recalbox 9.x (no dedicated logo field)

On Recalbox versions without a dedicated "logo" field:

1. Set **"Select thumbnail type"** to **"MARQUEE"**
2. Do NOT set **"Select image type"** to that value — it's used for another visual (box art, title screen...)
3. Run the scrape

Files are stored in `media/thumbnails/` for each system, referenced by the `<thumbnail>` tag. → Choose the **9.x** profile (recommended) in the tool.

### "legacy" profile (via the image field)

If your Recalbox setup scrapes the logo/marquee via **"Select image type"** (set to **"Clear Logo"** or **"Marquee"**), files are stored in `media/images/`, referenced by the `<image>` tag. → Choose the **legacy** profile. Reserve this for setups that don't use the thumbnail field for the logo.

```
📁 /recalbox/share/roms/
   ├── 📁 mame/
   │   ├── 📄 gamelist.xml
   │   ├── 📁 media/
   │   │   ├── 📁 wheels/         ← 10.x profile (<logo>)
   │   │   ├── 📁 thumbnails/     ← 9.x profile (<thumbnail>)
   │   │   └── 📁 images/         ← legacy profile (<image>)
   │   └── ...
   ├── 📁 snes/
   │   ├── 📄 gamelist.xml
   │   ├── 📁 media/
   │   │   └── 📁 wheels/
   │   │       └── 🖼️ supermetroid.png
   └── ...
```

> **💡 Tip**: Use Screenscraper.fr or TheGamesDB for best results!
>
> **💡 Already scraped with a different config?** Use the **"Clean folders before scraping"** button (Mode 1/3) before running a fresh Recalbox scrape, so you don't mix old artwork with the new one.
>
> **💡 Not sure about the images you got?** Run **Mode 8** to generate a report of images missing or inconsistent with the chosen profile.

### 🪛 Assembly Steps

**Step 1 — Join the two panels**

Follow these steps to assemble your DMD panel in under five minutes, even if you have no DIY experience. First, join the two panels using the union pieces that come with the DMDos Board. Screws are not included, but any M3 screw you have at home will do — for example, from a power strip.

**Step 2 — Position the DMDos Board**

Join the panels ensuring the orientation of the back components is the same on both sides. Once joined, you'll see two identical connectors where you can place the DMDos Board: one is **input**, the other **output**. Place the board on the **input** connector, in the orientation that lets you position it easily without hitting the plastic bracket. ⚠️ It only works on the input connector.

**Step 3 — Power wiring**

Once the board is connected, and **before** placing the ESP32 on top, connect the red and black power cables from both panels to the DMDos board's terminals, as indicated by the silkscreen: red on one side, black on the other. You can keep the connectors that come with the cables and screw down only one pin, or cut the remaining pin or strip the whole cable so it fits completely into the terminal. Also connect the two panels together with the included ribbon cable.

**Step 4 — SD card, ESP32 and power**

Finally, insert the previously prepared micro-SD card (see [Recommended Workflow](#-recommended-workflow)) and plug in the ESP32 already flashed with the **RecalBoxDMD** firmware (see [ESP32 Firmware](#-esp32-firmware--raw565-edition)) on top. All that's left is to power it via the USB-C port.

## ⚡ ESP32 Firmware — Raw565 Edition

### 💡 Why raw565?

The **raw565** format is the key element of this version. Here's why:

```
┌────────────────────────────────────────────────────────────────┐
│                       SD CARD                                   │
│                                                                │
│  PNG (50 KB)  →  PC Conversion →  .raw565 (8,192 bytes)       │
│  GIF (200 KB) →  PC Conversion →  .raw565pack + .meta          │
│                                                                │
│  The ESP32 only needs to:                                      │
│    1. Open the .raw565 file (8 KB)                             │
│    2. Read 8192 bytes into RAM                                 │
│    3. drawRGBBitmap() → direct display                         │
│                                                                │
│  🚀 Total time: 5-15 ms (vs 500ms-3s for PNG/GIF)             │
└────────────────────────────────────────────────────────────────┘
```

### 📡 MQTT — The system's brain

MQTT allows Recalbox to communicate with the ESP32 in real time:

```
Recalbox → marquee[rungame,...].sh → MQTT → ESP32 → LED Panel

1. You launch "King of Fighters '98"
2. The bash script detects the event → sends "mame/kof98" via MQTT
3. ESP32 receives → looks in order:
   a. /systems/mame/kof98.raw565      ← instant (5 ms)
   b. games_cache.bin → bigram        ← accelerated indexing
   c. /systems/_defaults/mame.raw565  ← system fallback
   d. /systems/_defaults/default.raw565 ← global fallback
4. Displayed in under 15 ms!
```

Place `marquee[rungame,endgame,systembrowsing,...].sh` in:
```
/recalbox/share/userscripts/
```

## 🗂️ The raw565 Format in Detail

### 📄 .raw565 (still image from PNG)

```
Size: 128 × 32 × 2 = 8,192 bytes exactly
Format: Raw RGB565 (16 bits per pixel)
         Bit R: bits 15-11 (5 bits)
         Bit G: bits 10-5  (6 bits)
         Bit B: bits 4-0   (5 bits)

ESP32 reading:
  f.read(buffer, 8192);
  drawRGBBitmap(0, 0, buffer, 128, 32);
  // 1 SD operation + 1 draw → 5 ms
```

### 🎞️ .raw565pack + .meta (animated GIF)

The **`.raw565pack`** file concatenates all GIF frames:

```
[Filename].raw565pack
├── Frame 0  →  8,192 bytes (raw565)
├── Frame 1  →  8,192 bytes
├── Frame 2  →  8,192 bytes
├── ...
└── Frame N  →  8,192 bytes

[Filename].meta
├── delay_0  →  2 bytes (uint16, milliseconds)
├── delay_1  →  2 bytes
├── delay_2  →  2 bytes
└── ...
```

**Advantages**:
- **1 SD open** to read a frame (seek + bulk read)
- **No GIF decoding** on ESP32
- Accelerated reading via RAM-delay cache (`.meta` loaded once)
- Built-in speed control (`GIF_RAW_PACK_SPEED_PERCENT`)

### ⚡ Bigram Cache — accelerated indexing

To avoid listing SD folders (very slow with 30,000 files), the script builds a **bigram index**:

```
games_cache.bin
├── [Header]  → number of indexed systems
├── [System 0] → name + bigram table offset
├── [System 1] → name + offset
└── ...

Bigram table (703 entries = 2812 bytes per system)
├── Index 0   → '#'  (digits, symbols)
├── Index 1   → 'A'  (games starting with A)
├── Index 2   → 'AA' (games starting with AA)
├── Index 3   → 'AB'
├── ...
└── Index 702 → 'ZZ'

Each entry = offset in the cache file pointing to the game list
```

When the ESP32 searches for `kof98`:
1. Calculates bigram index: `K` → index `11*27+1=298` (prefix `KO`)
2. Loads the corresponding slice into RAM (bulk read)
3. Scans game names in this slice
4. Finds `kof98` and its type (`p` for raw565) → **instant**

### 🎭 Mask system

For very large systems (MAME, FBNeo, etc.), the mask mechanism prevents black screens:

```
┌─────────────────────────────────────────────────────────────┐
│  Step 1: Python script analyzes the system                 │
│  → Counts individual files                                 │
│  → >800 files? Flag "L" in systems_cache.dat               │
│                                                             │
│  Step 2: ESP32 receives "mame/kof98"                       │
│  → System MAME flagged "L"?                                │
│    YES → Displays IMMEDIATELY the default raw565            │
│           (preloaded in RAM, 0 ms wait)                    │
│                                                                   │
│  Step 3: In parallel, async task:                         │
│  → Looks for the specific .raw565                          │
│  → Not found? Decodes the PNG in background task          │
│  → When ready: replaces mask with the real image           │
│                                                             │
│  Result: User never sees a black screen!                   │
└─────────────────────────────────────────────────────────────┘
```

## 🔧 Troubleshooting

### ❌ Problem: "Pillow is not installed"
- The script tries to install it automatically
- If it fails, run manually: `pip install Pillow`

### ❌ Problem: "GitHub API unreachable"
- Check your internet connection
- The _defaults modes require a connection

### ❌ Problem: "No removable drive detected"
- Insert your SD card
- Check it's detected by Windows (Explorer → This PC)
- Try again

### ❌ Problem: ESP32 displays nothing
- Check power supply (5V 4A minimum)
- Check config.ini is at the SD card root
- Check HUB75 wiring (ESP32 pinout)
- Try Telnet: type `help` to test

### ❌ Problem: "ESP32 not detected" (COM port missing)
Install USB drivers:

| USB Chip | Drivers |
|----------|---------|
| CP2102 | [Silicon Labs](https://www.silabs.com/developers/usb-to-uart-bridge-vcp-drivers) |
| CH340/CH341 | [SparkFun](https://learn.sparkfun.com/tutorials/how-to-install-ch340-drivers/all) |

### ❌ Problem: Slow display or black screen between games
- Make sure you are using **Mode 1** (full raw565 conversion)
- Large systems (MAME, FBNeo) should be flagged **"L"** — check in `systems_cache.dat`
- If the flag is `N` (fast) but the system is slow, increase `SPRITE_LIMIT` in the .ino
- Check that `.raw565` files exist in `systems/<sys>/`

### ❌ Problem: Image not displaying on panel
- Make sure the image is in 128x32 format
- PNGs must be in RGB (not RGBA) for conversion
- raw565 files take priority over raw565pack

### ❌ Problem: Wrong image shows up (box art instead of logo/marquee)
- This is usually a Recalbox Scraper field misconfiguration — check the **"Recalbox version"** profile (Mode 1/3) and click **"How to scrape?"** for the exact steps for your version
- Use **"Clean folders before scraping"**, then run a full Recalbox scrape with the correct setting
- Run **Mode 8** to check which images are actually present
